# 権限マトリクス

ロールごとの操作権限を定義する。

## ロール定義

| ロール      | 説明           | 用途                                                                       |
| ----------- | -------------- | -------------------------------------------------------------------------- |
| **admin**   | システム管理者 | プラットフォーム全体の管理。システム設定・権限設定を含むすべての操作が可能 |
| **owner**   | 運営者         | コミュニティの運営管理。コンテンツ管理・メンバー管理などの運営業務を担当   |
| **member**  | メンバー       | コミュニティの一般参加者。有効化された機能の閲覧・投稿・参加が可能         |
| **visitor** | ビジター       | 限定的なアクセス権を持つユーザー（未実装）                                 |

## 凡例

- **C** = 作成（Create）
- **R** = 閲覧（Read）
- **U** = 更新（Update）
- **D** = 削除（Delete）
- **-** = 権限なし
- **自** = 自分のデータのみ操作可能
- **(feat)** = フィーチャー設定で有効化が必要

## 補足

### PermissionSetting による動的権限制御

上記のマトリクスはバックエンドのガード（`@Roles` デコレーター）に基づく**固定権限**である。
これに加えて、`PermissionSetting` モデルによる**動的権限制御**が存在する。

```
PermissionSetting {
  featureKey   // 機能キー（例: board, event）
  action       // アクション（例: create, update, delete）
  allowedRoles // 許可ロール（JSON配列）
  requiredRank // 必要ランク（MemberRank、オプション）
}
```

管理画面（設定 > システム設定 > 権限設定）から、機能ごとに細かいロール・ランク制御を追加設定可能。

### visitor ロールについて

visitor は Prisma スキーマに定義済みだが、現時点でフロントエンド・バックエンドともに具体的な権限は未実装。今後、限定公開コンテンツの閲覧権限など、member より制限されたアクセスを想定。
