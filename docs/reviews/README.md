# レビュー結果保存先

`/review` スキル実行時に、自動的にこのディレクトリへマークダウンとして保存される。

## このディレクトリの位置づけ

- **セルフレビュー専用**: 開発者が自分のコードを `/review` で点検し、指摘事項を整理する
- **コードの自動修正は行われない**: スキルは指摘のみを抽出する
- **修正判断は自身で行う**: 各指摘について「直す」「直さない（後回し）」「却下」を判断する

## ファイル名規則

```
{YYYY-MM-DD}-{scope-slug}.md
```

例:
- `2026-04-25-board.md`
- `2026-04-25-events-service.md`
- `2026-04-25-board-2.md`（同日同スコープの 2 回目）

## ファイル内容

各ファイルにフロントマターを付与:

```yaml
---
date: 2026-04-25
scope: apps/api/src/board/
branch: feature/phase-11.2-perf
reviewer: claude-code (/review)
total_findings: 8
high: 2
medium: 3
low: 3
checked_items: 64
---
```

本文は `.claude/skills/review/SKILL.md` の出力フォーマットに従う。

## 優先度（3 段階）

| マーク | 優先度 | 内容 | 対応の目安 |
|---|---|---|---|
| 🔴 | **高** | セキュリティリスク・データ不整合・本番障害につながる規約違反 | リリース前 / マージ前に修正必須 |
| 🟡 | **中** | 保守性・パフォーマンスへの中程度の影響、暫定運用は可 | 次のスプリント等で計画的に修正 |
| 🟢 | **低** | コード品質・スタイル・将来の改善候補、影響軽微 | 余裕がある時 / 該当箇所を触る時に対応 |

## 運用ガイド

### レビュー実施のタイミング
- 機能実装が一区切りついた時
- PR を出す前
- 大きなリファクタリングの後
- リリース前の総点検

### 結果の扱い方
- **🔴 高は必ず確認** → 修正 or 例外的に放置する理由を明確化
- **🟡 中は計画化** → タスク登録 / 別 PR で対応
- **🟢 低は余裕あれば** → 触ったついでに直す程度

### 古いレビューの整理
- 解決済みの指摘事項を含むレビューは、定期的に削除してよい（git 履歴で追える）
- リリース前のレビューは `release-{version}/` フォルダにアーカイブ推奨
- 同じファイルを何度もレビューする時は、過去レビューと比較して「前回からの新規問題」を特定可能

### git 管理
- このディレクトリは git 管理する（チームで指摘内容を共有可能）
- `.gitignore` には含めない
