# コミット

## 行動ルール（厳守）

1. ステージングにファイルがなければ **即座に中止** する。勝手にステージングしない。
2. `main` または `dev` ブランチで作業中の場合、**警告を表示** してユーザーに確認を求める。
3. コミットメッセージは **Conventional Commits の形式に厳密に従う**。
4. git コマンド実行時のエラーは **適切にハンドリング** してユーザーに報告する。
5. ユーザーが `n` を選択した場合、**コミットを中止** し変更を保持する。
6. `push` が引数で指定されていない場合、**push は絶対に行わない**。
7. push 失敗時、コミットはそのまま保持し **エラーの詳細と対処方法** を提示する。
8. ユーザーのステージング状態を **勝手に変更しない**（`git add` / `git reset` を実行しない）。
9. `--force` を使用した push を **許可なく行わない**。

---

## 手順

### 1. 状態確認

以下のコマンドを **並列** で実行する:

- `git status -s` — 変更ファイル一覧を取得
- `git diff --cached --stat` — ステージ済みファイルの概要を取得
- `git log --oneline -5` — 直近のコミットスタイルを参照
- `git branch --show-current` — 現在のブランチ名を取得

### 2. ガードチェック

以下の条件で処理を分岐する:

- **ステージ済みファイルがゼロ** → 「ステージングされたファイルがありません。`git add` でファイルをステージしてから再実行してください。」と報告して **終了**
- **現在のブランチが `main` または `dev`** → 「⚠ 現在 `{ブランチ名}` ブランチで作業中です。このままコミットしますか？」とユーザーに確認を求める。`n` なら **終了**

### 3. 差分の分析

`git diff --cached` でステージ内容の全差分を取得し、以下を分析する:

- 変更の種類（新機能追加、バグ修正、リファクタリング、ドキュメント、設定変更 等）
- 変更の範囲（どのモジュール・機能に影響するか）
- 変更の目的（なぜこの変更が必要か）

### 4. コミットメッセージ生成

引数 `$ARGUMENTS` に `push` 以外のメッセージが渡された場合はそれをそのままコミットメッセージとして使用する。
渡されていない場合は、以下の規約に従ってメッセージを生成する:

**Conventional Commits 形式（厳守）**:

```
<type>: <日本語の説明>
```

- **type** は以下のいずれか: `feat`, `fix`, `refactor`, `docs`, `chore`, `style`, `test`, `ci`, `perf`, `build`
- **説明** は日本語で1〜2文、簡潔に（「何を」「なぜ」がわかるように）
- 直近のコミットメッセージのスタイルに合わせる
- スコープが明確な場合は `feat(auth):` のように括弧付きスコープも可

**例**:

```
feat: アンケート回答ページにバリデーション追加
fix: ログイン画面で設定APIが401を返す問題を修正
refactor: hooks をドメイン別サブディレクトリにグルーピング
docs: CLAUDE.md を追加（開発ルール・命名規則）
feat(shop): 商品画像カルーセルを追加
```

### 5. コミット実行

HEREDOC 形式でコミットメッセージを渡す。フッターに Co-Authored-By を付与する。

```bash
git commit -m "$(cat <<'EOF'
{生成したコミットメッセージ}

Co-Authored-By: Claude Opus 4.6 (1M context) <noreply@anthropic.com>
EOF
)"
```

**エラー時**:

- pre-commit hook で失敗した場合 → エラー内容を分析してユーザーに報告する。修正後に **新しいコミット** を作成（amend しない）
- その他の git エラー → エラーメッセージを表示し、原因と対処方法を提示する

### 6. push（引数に `push` が含まれる場合のみ）

`$ARGUMENTS` に `push` という文字列が含まれている場合 **のみ**、コミット成功後に push を実行する。
引数に `push` がない場合は **このステップを完全にスキップ** する。

1. `git rev-parse --abbrev-ref --symbolic-full-name @{u}` でリモート追跡ブランチを確認
2. 追跡ブランチがある場合 → `git push`
3. 追跡ブランチがない場合 → `git push -u origin {現在のブランチ名}`

**push 失敗時**:

- コミットはそのまま保持する（取り消さない）
- エラーの詳細を表示する
- 対処方法を提示する（例: 「`git pull --rebase` してから再度 push してください」）

### 7. 結果報告

- コミットが成功した場合 → コミットハッシュとメッセージを表示
- push した場合 → push 先のリモート・ブランチ名を表示
- エラーが発生した場合 → エラー内容と対処方法を表示

## 禁止事項

- `--amend` は使わない（前のコミットを壊す可能性がある）
- `--no-verify` は使わない（hook をスキップしない）
- `--force` / `--force-with-lease` push は許可なく使わない
- `git add` / `git reset` でユーザーのステージング状態を変更しない
- 引数に `push` がない限り push しない
